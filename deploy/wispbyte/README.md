# بوت‌استرپِ Wispbyte — نسخه‌ی اصلاح‌شده‌ی `main.py`

این پوشه همان `main.py`ای است که روی میزبانِ «اپ پایتونیِ» Wispbyte اجرا می‌شد
(کلونِ `abolfazleoy/jfjj` در `./code`، ساختِ `./venv`، نصبِ وابستگی‌ها، و بعد
اجرای `railway-start.sh`)، با شش اصلاحِ واقعی.

## چرا این فایل مهم است

روی Wispbyte **کدی که اجرا می‌شود `./code/95.py` است**، نه فایلی که در ریشه‌ی
اپ می‌گذاری. اگر `95.py` را در ریشه آپدیت کنی، هیچ اثری ندارد و از بیرون
«عینِ قبل» دیده می‌شود. این نسخه همین را با مقایسه‌ی هشِ دو فایل صریح می‌گوید.

## شش اصلاح

| # | قبلاً | حالا |
|---|---|---|
| ۱ | `pip install "telethon&gt;=1.34.0"` (HTML-escape) → همیشه شکست | `telethon>=1.34.0` |
| ۲ | آدرسِ کلون با توکنِ گیت در لاگ چاپ می‌شد | `redact()` — توکن/`:token=`/`https://***@` ماسک می‌شود |
| ۳ | شکستِ `git fetch` بی‌صدا → کدِ قدیمی می‌ماند و آپدیت بی‌اثر است | `⛔` + کامیتِ فعلی + علت‌های رایج؛ `commit`/`stale` در `/health` |
| ۴ | شکستِ نصبِ وابستگی‌ها فقط لاگ می‌شد و ادامه می‌داد | `die` با مسیرِ همان مفسر و دستورِ نصبِ درست |
| ۵ | پوشه‌ی دادهٔ غیرقابلِ‌نوشتن بی‌صدا به `/tmp` می‌رفت | هشدارِ صریح + `data_tmp` در `/health` (دادهٔ موقت = از دست رفتنِ سشن) |
| ۶ | `95.py`ِ ریشه با `code/95.py` فرق می‌کرد و گفته نمی‌شد | هشدارِ «آپدیتِ فایلِ ریشه اثری ندارد» با هر دو هش |

## نصب

1. همین فایل را روی میزبان، به‌جای `main.py`ِ ریشه بگذار.
2. دستورِ شروع همان `python main.py` می‌ماند.

## بررسیِ اینکه آپدیت رسید یا نه

```bash
curl -s http://127.0.0.1:$PORT/ | python3 -m json.tool
```

```json
{"ok": true, "boot": true, "mode": "manager",
 "version": "2026-11-02-slim2",
 "commit": "a5a9482", "stale": false, "why": "",
 "deps": true, "python": "/app/venv/bin/python",
 "data": "/data", "data_tmp": false}
```

- `commit` = کامیتی که **واقعاً** اجرا می‌شود؛ با `git -C code log -1 --oneline` و
  گیت‌هاب مقایسه کن.
- `stale: true` = به‌روزرسانی از گیت شکست خورده و کد قدیمی است (`why` علتش).
- `deps: false` یا `data_tmp: true` = همان دو دامی که «سلف بالا نمی‌آید» را
  می‌سازند.
